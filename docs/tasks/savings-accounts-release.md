# Выпуск учёта накоплений

Первая версия реализует согласованные решения из [плана](savings-accounts-plan.md).

## Поведение

- `/assets`: наличные, банковские счета, вклады и инвестиции, фильтры по типу/месту, архив, итог в выбранной валюте. RU/EN интерфейс и светлая/тёмная темы.
- Наличные/банк: несколько валют. Вклад: одна валюта, ставка, даты открытия/окончания. Инвестиции: общая оценка счёта, включая свободные деньги, в одной валюте; обновляется вручную.
- Начальный остаток и последующие сверки сохраняются с точным временем. Остаток — последняя сверка плюс движения строго после неё. Старые поздно внесённые операции не изменяют подтверждённую сумму. Разница с расчётным остатком показана в журнале и не становится доходом/расходом.
- Доход/расход может необязательно ссылаться на денежный счёт. Обычные операции с инвестиционным счётом не привязываются: доступны переводы и оценка всего счёта.
- Свои переводы, снятие в наличные, пополнение брокера и обмен валют не попадают в доходы/расходы. «Вне учёта» позволяет отражать пополнение/снятие без второй заведённой стороны.
- Курсы в сводке — сохранённые вручную прямые пары из `FxRepo`, с датами. Отсутствующий курс помечает итог как неполный. Котировки, позиции, бумаги, доходность и импорт брокеров отложены.
- Отрицательные остатки допустимы и выделены предупреждением. Архив требует нулевых остатков и отсутствия будущих движений/сверок. Пустой счёт без истории можно удалить.

## API и хранение

`proto/budget/v1/asset.proto` добавляет tenant-scoped `AssetService`: CRUD счетов, архив/восстановление, сверки, переводы, сводка и журнал. `transactions.asset_account_id` и два `currency_exchanges.*_asset_account_id` nullable; старые операции остаются без связи. В update транзакции связь управляется маской `asset_account_id`; в update обмена оба optional-поля отсутствуют у старых клиентов и сохраняют связь, два явных пустых значения отвязывают её.

Суммы в младших единицах int64; UI использует bigint, без промежуточного float. Все ноги движения и исходная запись записываются одной PostgreSQL-транзакцией. Версии защищают редактирование счетов, сверок и переводов. `request_key` защищает создание от повторной отправки; результат и hash входных данных сохраняются вместе с записью. Изменение содержимого под тем же ключом возвращает конфликт.

TenantGuard защищает все RPC нового сервиса. Чтение/изменение/удаление существующих операций через gRPC теперь ограничено активным tenant, включая связанные счета.

## Миграция и откат

`0010_assets.up.sql` добавляет таблицы счетов, сверок, переводов, движений и ключей повторных запросов; существующие деньги и категории не пересчитывает. Backend применяет встроенные миграции при старте. SQL допускает повторное применение штатным initContainer.

До выпуска сохранена production копия PostgreSQL `/root/budget-release-backups/pre-assets-20261003.dump`; 248345 байт, список объектов прочитан `pg_restore --list`. До выпуска backend/web работали с digest `d840b9dbb05295f4c4d570cb26df327d02632e6d01cc6ea118a42e829255ca87` / `fdcac7c746a679a1241f8dbf6fdbb8098078d6511a1a34d034b110762add9094`.

После использования новой функции нельзя откатывать backend на старую версию с разрешёнными изменениями операций: она не обслуживает журнал движений. Предпочтителен исправляющий выпуск. Для вынужденного отката сначала остановить записи, сохранить свежую копию и согласовать восстановление/пересчёт. Down-миграция удаляет весь новый учёт и связи; её не применяем автоматически при откате образа.

## Публикация

CI default-ветки публикует backend/web в GHCR; Flux обновляет digest и rollout. Завершение выпуска подтверждается отдельно состоянием GitHub Actions, digest работающих pod, версией миграции, логами backend и публичной страницей `/assets`.
